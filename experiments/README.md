# WhisperKit: экспериментальный движок

WhisperKit входит в единственное приложение **bleep.ly**, рядом с CPU и MLX.
Отдельной Lab-сборки больше нет; движок остаётся экспериментальным и выбирается вручную.

## Запуск

Из корня проекта (существующие `.venv`, FFmpeg и Swift toolchain обязательны):

```sh
bash scripts/build-macos.sh
.venv/bin/python -m pip install -r requirements-whisperkit.txt
.venv/bin/python scripts/prepare-whisperkit.py
open 'build/bleep.ly.app'
```

Первичная сборка скачивает Swift-зависимости. Шаг prepare-whisperkit явно скачивает около
1.7 GB весов и токенизатора в `.cache/whisperkit/model`; записи никуда не отправляются.
Вместо запуска prepare-whisperkit можно один раз разрешить `Allow first-time model download`
в настройках приложения. После установки моделей распознавание работает offline.
Во время первой загрузки приложение показывает полученные и общие MB,
затем установку модели и отдельный этап подготовки Core ML.
Первый запуск Core ML может занимать несколько минут; это подготовка модели.

`⌘,` → `Recognition` → `Engine` → `WhisperKit · Experimental`.
Единый список CPU / MLX / WhisperKit применяется к следующему открытому файлу в Fast и Advanced.
Для оценки качества удобнее Advanced: сначала прослушать находки и пропуски,
затем экспортировать. Чтобы вернуться к CPU или MLX, выберите его в том же списке.
Старый включённый переключатель Lab автоматически переносится в этот выбор.
Импорт проверенной расшифровки всегда сохраняет её ручные флаги и интервалы.

Единственная сборка: `bash scripts/build-macos.sh`. Приложение использует `icon.PNG`;
скрипт создаёт macOS `.icns` со всеми размерами, исходный PNG не меняется.

## Что сравниваем

WhisperKit — другой runtime и Core ML-конверсия семейства **large-v3-turbo**,
а не автоматически более точная модель. Закреплены:

- SDK [argmax-oss-swift 1.1.0](https://github.com/argmaxinc/argmax-oss-swift/releases/tag/v1.1.0),
  commit `1e2a163736dfa5a198e637ae44c114e1c6d5cc2d`.
- [Core ML weights](https://huggingface.co/argmaxinc/whisperkit-coreml):
  `openai_whisper-large-v3-v20240930_turbo`, revision
  `0f63a7800b00dd0226abd051b906c246e1907482`.
- [Tokenizer](https://huggingface.co/openai/whisper-large-v3-turbo), revision
  `41f01f3fe87f28c78e2fbf8b568835947dd65ed9`.

Swift helper запускается из Python отдельным процессом, в группе отменяемого
задания. Возвращает слова, таймкоды и диагностические метрики. Ошибка helper
показывается как ошибка: скрытого перехода на другой движок нет. Поиск мата,
ручные правки, интервалы mute и экспорт общие для всех движков.

Настройки сравниваемых **продуктовых pipelines различаются**:

- CPU: faster-whisper, int8, beam 5, VAD, без initial prompt.
- MLX: float16, greedy, VAD, существующая русская подсказка.
- WhisperKit: Core ML default compute units, русский язык, word timestamps,
  incremental audio loading/VAD, один worker, temperature 0 и до пяти
  стандартных temperature fallbacks, suppressBlank, maxInitialTimestamp 1s,
  без initial prompt. Повторные попытки могут менять текст между запусками.

При диагностике на локальном образце подсказка из MLX в WhisperKit дала сильное
смещение таймкодов. Поэтому здесь она не используется. Отключение fallbacks при
сохранённом SDK first-token threshold могло дать пустую расшифровку; оставлены
стандартные повторные попытки. Эти наблюдения относятся к данной версии и
конфигурации, не являются выводом о WhisperKit в целом.

## Воспроизводимое сравнение

```sh
HF_HOME="$PWD/.cache/huggingface" HF_HUB_DISABLE_TELEMETRY=1 \
  .venv/bin/python -m censor.benchmark input.mov \
  --reference input.reviewed.transcript.json \
  --helper 'build/bleep.ly.app/Contents/Helpers/BleepWhisperKit' \
  --output .cache/comparison-new --repeats 3
```

Папка вывода должна быть новой. Все модели заранее установлены; сетевые
загрузки выключены. Запуски последовательные, в новых процессах, с обязательным
обходом кэша расшифровок. Для нескольких аудиодорожек `--audio-stream` задаёт
номер **аудиодорожки с нуля**, как desktop API. При наличии SHA-256 в reference
проверяется совпадение исходного файла. Не запускать одновременно компиляцию,
другие модели или тяжёлые приложения во время измерения.

`report.json` содержит каждый запуск и метрики; рядом request/event/stderr/review
файлы. Metadata в `cache/` содержит версии, настройки, хэш helper и идентичность
весов. Всё это игнорируется Git. Исходник и проверенная расшифровка не меняются.

Время wall включает запуск Python, извлечение аудио, загрузку и распознавание;
analysis_seconds исключает только старт Python. Первый Core ML запуск считать
отдельно от повторных; системные/model caches между ними остаются прогретыми.
`peak_memory_bytes` у helper не включает всю память системных Core ML сервисов
и не годится для прямого сравнения общей памяти приложения.

Метрики качества:

- Recall/precision найденных **вхождений мата**: однозначное сопоставление
  с отмеченными в reference словами, разница центров не более 0.5s. Допускаются
  разные написания ругательства. Это проверка обнаружения возле нужного места,
  а не гарантия чистого звука.
- Ошибка границ в секундах только у сопоставленных находок; пропуски приведены
  отдельно и остаются в знаменателе recall.
- Lexical disagreement: расстояние Левенштейна слов / число слов reference,
  без регистра/пунктуации, ё→е. Это **не независимая оценка WER**: исходная
  расшифровка CPU исправлялась частично и даёт этому движку преимущество.

Четырёх ругательств в одном ролике недостаточно для решения о релизе. Нужны
дополнительные вручную размеченные записи: тихая речь, музыка, перекрывающиеся
голоса, быстрый темп и длинные файлы; затем прослушивание экспортированного
результата. Даже при полном recall приблизительные word timestamps могут
оставить начало ругательства слышимым.

## Первый локальный результат · 2026-10-08

На `input.mov` (19.93s), относительно четырёх проверенных вхождений:

| Pipeline | Найдено в правильном месте, 3 прогона | Повторный запуск, wall |
| --- | --- | --- |
| faster-whisper CPU | 3 / 4 во всех | 7.54–7.92s |
| MLX | 4 / 4 во всех | 3.77–4.18s |
| WhisperKit | 2 / 4, 3 / 4, 3 / 4 | 4.33–4.75s |

Полный первый запуск WhisperKit из `.app` занял 174.24s, включая подготовку
Core ML. В таблице скорость только прогонов 2–3: при первом проходе CPU/MLX
параллельно ещё завершалась сборка, поэтому его время не используем для сравнения.
Все три прогона сохранились в `.cache/whisperkit-benchmark/final/report.json`.

CPU и WhisperKit пропустили проверенное вхождение около 11s. Ошибка начала
первого ругательства у всех движков достигает примерно 0.55–0.57s, несмотря
на совпадение самого вхождения по метрике. MLX на этом образце лучше по полноте,
но автоматические интервалы всё равно нуждаются в прослушивании.

Это основание оставить WhisperKit экспериментом. Не менять движок по умолчанию
и не считать результат одного короткого образца доказательством общей точности.
